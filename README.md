
#  AI 오답 노트 챗봇

> **AI에게 질문하고, 중요한 내용을 기록하고, 퀴즈로 복습하는 학습 도우미**

Python과 Flask를 활용하여 개발한 웹 기반 AI 학습 챗봇입니다.

[🌐 웹사이트 바로가기](https://chatbot-project-euvr.onrender.com)

---

##  프로젝트 소개

공부나 과제를 하다가 이해하기 어려운 개념을 질문하거나 코드에 대한 도움을 받고,  
중요한 질문과 답변을 **오답 노트 형태로 저장하여 나중에 다시 복습할 수 있는 챗봇**입니다.
저장된 내용을 바탕으로 AI가 복습용 퀴즈를 생성하여 학습한 내용을 점검할 수도 있습니다.

###  개발 동기

공부나 과제를 하다가 AI에게 질문했던 내용을 나중에 다시 찾는 과정이 비효율적이라고 느꼈습니다.
그래서 질문과 답변 중 중요한 내용을 오답 노트처럼 저장하고, 필요할 때 쉽게 찾아보며 복습할 수 있는 프로그램을 만들고자 하였습니다.

###  예상 사용자

- 프로그래밍 언어를 공부하는 대학생
- 컴퓨터 전공 지식을 학습하는 학생
- 코딩을 처음 배우는 개발 초보자

---

##  사용 기술 및 참고 자료

- **Python / Flask**: AI 챗봇 기능 구현 및 웹사이트 개발
- **Mindlogic API Gateway**: LLM 모델과 프로그램 연결
- **GPT-5.6 Luna (LLM)**: AI 질문 답변 및 복습 퀴즈 생성
- **GPT-6**: 코드 작성, 오류 해결 및 기능 개선에 활용
- **SQLite**: 회원 정보 및 오답 노트 데이터 저장
- **Git / GitHub**: 프로젝트 코드 관리 및 개발 기록
- **Render**: 웹사이트 배포 및 업데이트

<summary><b>📍 2주차 — AI 챗봇 기본 기능 구현</b></summary>

###  이번 주에 한 일

- Python을 이용하여 AI 오답 노트 챗봇의 기본 기능 구현
- API를 연결하여 LLM이 사용자의 질문에 답변하도록 구현
- 과목을 추가하고 삭제할 수 있도록 구현

###  새롭게 알게 된 것

- Python에서 API를 이용하여 LLM과 연결하는 방법을 알게 되었다.
- Git의 `add`, `commit`, `push`를 이용하여 프로젝트 변경 사항을 GitHub에 저장하는 방법을 알게 되었다.
- `.gitignore`를 사용하여 API 키와 같은 파일이 GitHub에 올라가지 않도록 설정하는 방법을 알게 되었다.

###  어려웠던 점

- 처음에는 LLM API 연결과 Python 실행 환경을 설정하는 과정이 어려웠다.
- GitHub와 로컬 프로젝트를 연결하고 처음 코드를 업로드하는 과정에서 Git 충돌과 인증 문제가 발생하여 해결하는 데 어려움이 있었다.

###  다음 주에 할 일

- 현재 터미널에서 실행되는 챗봇의 화면 개선
- 사용자가 원하는 기능을 쉽게 선택할 수 있는 메뉴 또는 GUI 형태로 발전
- 오답 노트와 퀴즈 기능을 추가로 테스트하고 부족한 부분 수정

<details>
<summary><b>📍 3주차 — Flask 웹 화면 구현</b></summary>

###  이번 주에 한 일

- 기존에 터미널에서 실행하던 AI 오답 노트 챗봇을 Flask를 이용한 웹 형태로 구현
- 메인 화면에서 질문하기, 오답 노트, 퀴즈 풀기, 과목 관리 기능을 선택할 수 있도록 구성
- 질문하기 화면에서 과목을 선택하고 AI에게 질문할 수 있도록 구현
- AI의 답변을 선택한 과목의 오답 노트에 저장할 수 있도록 기능 연결
- 오답 노트 화면에서 과목을 선택하면 해당 과목에 저장된 질문과 답변을 확인할 수 있도록 구현
- 저장된 오답 노트 내용을 바탕으로 과목별 복습 퀴즈를 생성하고 풀 수 있도록 웹 화면과 연결
- 과목 관리 화면에서 사용자가 원하는 과목을 직접 추가하고 삭제할 수 있도록 구현

###  새롭게 알게 된 것

- Flask를 이용하면 Python으로 구현한 기능을 웹 페이지와 연결할 수 있다는 것을 알게 되었다.
- 하나의 파일에 모든 기능을 작성하는 것보다 기능별로 파일을 나누고 `app.py`에서 연결하면 코드를 관리하기 편하다는 것을 알게 되었다.
- HTML의 `form`을 이용하여 사용자가 입력한 질문이나 선택한 과목 정보를 Python 코드로 전달할 수 있다는 것을 알게 되었다.

###  어려웠던 점

- 기존에는 터미널에서 각각 실행되던 기능들을 하나의 웹 화면에서 자연스럽게 연결하는 과정이 어려웠다.
- 기능을 추가하거나 화면을 수정할 때 기존 기능이 제대로 동작하는지도 함께 확인해야 해서 여러 번 테스트가 필요했다.
- 웹 화면을 구성하면서 내가 원하는 디자인과 AI가 만들어 주는 결과가 달라, 원하는 형태가 나오도록 계속 수정하고 AI와 맞춰가는 과정이 어려웠다.

###  다음 주에 할 일

- 웹에서 질문하기, 오답 노트, 퀴즈, 과목 관리 기능을 전체적으로 다시 테스트
- 사용하면서 발견되는 오류나 부족한 부분 수정
- 오답 노트와 퀴즈 기능의 사용 흐름 보완
- 웹 화면의 배치와 디자인을 보기 편하도록 개선

</details>

<summary><b>📍 4주차 — 회원 관리 및 프로젝트 최종 정리</b></summary>

###  이번 주에 한 일

- 회원가입, 로그인 및 로그아웃 기능 구현
- 사용자마다 과목과 오답 노트를 따로 관리할 수 있도록 기능 수정
- SQLite 데이터베이스를 이용하여 사용자 정보와 학습 내용 저장
- GitHub에 포함된 불필요한 파일 및 민감한 정보의 커밋 기록 정리
- GitHub 업데이트 화면, 주요 진행 사항, 프로그램 구조도 및 실행 흐름도를 정리한 PPT 제작
- README의 내용 수정 및 가독성 개선
  
###  새롭게 알게 된 것

- Flask에서 세션을 이용하면 로그인한 사용자의 정보를 유지하고, 사용자마다 다른 화면과 데이터를 제공할 수 있다는 것을 알게 되었다.
- SQLite 데이터베이스를 이용하면 사용자 정보와 과목, 오답 노트 등을 파일로만 저장하는 것보다 체계적으로 관리할 수 있다는 것을 알게 되었다.
- 회원가입과 로그인 기능을 구현할 때 비밀번호를 그대로 저장하지 않고 해시 값으로 저장해야 한다는 것을 알게 되었다.
- GitHub에 실수로 중요한 파일을 업로드한 경우, 단순히 파일을 삭제하는 것뿐만 아니라 이전 커밋 기록까지 확인하고 정리해야 한다는 것을 알게 되었다.

###  어려웠던 점

- 로그인한 사용자에 따라 과목과 오답 노트를 구분하여 저장하도록 수정하는 과정이 어려웠다.
- GitHub에 데이터베이스와 비밀키 파일이 포함되어 이전 커밋 기록까지 정리하는 과정에서 어려움이 있었다.
